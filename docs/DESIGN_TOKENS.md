# Sesame Notes 设计 Token 与界面基线

本文记录当前客户端的主题、组件和导航约束。具体色值和状态实现以源码为准，不在文档中维护另一份亮暗色板。

## 1. 职责与源码

| 位置 | 职责 |
| --- | --- |
| [app_visual_theme.dart](../lib/theme/app_visual_theme.dart) | `AppThemePreset`、颜色/几何角色与 `ThemeExtension` |
| [app_theme_presets.dart](../lib/theme/app_theme_presets.dart) | 经典蓝、极简清单、温暖手账的浅色/深色六套参数 |
| [app_theme.dart](../lib/theme/app_theme.dart) | 按「风格 + 明暗 + 平台」缓存并装配 `ThemeData` |
| [colors.dart](../lib/theme/colors.dart) | 业务组件读取颜色、圆角、边框、阴影和纸面质感的 `AppTokens` 入口 |
| [typography.dart](../lib/theme/typography.dart) | `AppTextTokens`、系统字体、展示文字与金额输入样式 |
| [dimens.dart](../lib/theme/dimens.dart) | 结构间距、图标、点击区域、列表和专用控件尺寸 |
| [chart_tokens.dart](../lib/theme/chart_tokens.dart) | 图表尺寸、线宽、标注和分类配色 |
| [theme_providers.dart](../lib/shared/providers/theme_providers.dart) | 外观偏好恢复、即时应用、保存反馈与重试 |

通用约束：

- 颜色、字号、间距、圆角先查已有语义 Token 和共享组件；业务页面不直接判断主题名称或复制十六进制色值。
- 主题改变视觉角色，不改变账本、账号、统计口径、数据协议、业务权限和表单草稿。
- 静态品牌资源保留自己的颜色。默认头像使用 `assets/Default avatar.png`，品牌 Logo 使用 `assets/app_logo.svg`；生成流程见[工具入口的图标说明](../scripts/README.md#图标与品牌资源)。
- 新组件优先组合既有组件。不要为了一个页面另建平行的按钮、日期选择器、单选行或本子编辑流程。

## 2. 应用主题与显示模式

「我的 → 外观与主题」提供两个独立选择：

| 选择 | 值 | 保存规则 |
| --- | --- | --- |
| 应用主题 | `classic` / `minimal` / `journal` | 本地 `appVisualTheme`；未知值回退经典蓝 |
| 显示模式 | 跟随系统 / 浅色 / 深色 | 沿用 `themeMode`；换风格不改变明暗偏好 |

点选后即时应用。保存失败时保留已应用外观，展示可重试的未保存提示，不回滚业务状态。主题重建不得重置路由、当前本、账期、选中日期、滚动位置、已打开弹层或输入控制器。

`ThemeData` 缓存键必须包含风格、亮暗和平台；仅按亮暗缓存会在换风格后读到错误外观。弹层应读取导航层的当前主题，不能长期持有打开时的默认颜色快照。

### 几何角色

以下是当前三套主题的逻辑像素参数；浅深模式共用同一套几何。后续调整从预设源码集中维护。

| 角色 | 经典蓝 | 极简清单 | 温暖手账 | 访问入口 |
| --- | ---: | ---: | ---: | --- |
| 普通卡片 | 12 | 8 | 14 | `cardRadius(context)` |
| 摘要/强调卡片 | 20 | 10 | 18 | `heroRadius(context)` |
| 按钮 | 12 | 6 | 10 | `buttonRadius(context)` |
| 输入/选择字段 | 12 | 6 | 10 | `inputRadius(context)` |
| 普通弹层 | 24 | 16 | 24 | `sheetRadius(context)` |
| 记账编辑弹层 | 28 | 20 | 28 | `entrySheetRadius(context)` |
| 数字键 | 11 | 6 | 10 | `keyRadius(context)` |

`AppDimens.radius*` 是固定尺寸，不应通过改写这些常量切换主题。主题化组件使用以上动态角色；确有固定几何的图标、头像和日期标记继续使用自己的尺寸 Token。

分组列表通过 `AppTokens.listGroupsUseCards(context)` 选择卡片表面，通过 `AppTokens.listGroupHeadingGap(context)` 读取标题后留白。极简清单使用平铺分组和 0dp 留白，经典蓝与温暖手账使用卡片和 12dp 留白；角色配置集中在视觉预设，业务页面不判断风格名称。

## 3. 颜色、边框与阴影

动态皮肤颜色只有一个来源：[app_theme_presets.dart](../lib/theme/app_theme_presets.dart)。`AppVisualTheme` 选择对应风格与明暗配置，`AppTokens` 和 `AppTheme` 负责语义访问及 Material 装配。`ColorScheme.fromSeed` 的输入直接来自当前皮肤的 `brand`，不再有另一份全局静态主色。

跨主题固定色与皮肤色分开管理：`AppColors` 仅保留实际使用的警告亮暗值及本机、Supabase、WebDAV、S3、云服务品牌色；警告值可区分明暗，但不随风格改写。媒体预览的固定暗背景、浅前景和遮罩留在各自媒体 Token 中。不要把这些固定用途复制成第二份页面、卡片或输入框色板。

| 角色 | 建议入口 | 使用要求 |
| --- | --- | --- |
| 页面 | `scaffoldBackground` | 页面与嵌入内容背景 |
| 内容卡片 | `surface` | 普通卡片表面 |
| 次级表面 | `surfaceSecondary` | 输入区域、标签等次级层 |
| 弹层表面 | `surfaceSheet` / `surfaceElevated` | 读取当前皮肤的 raised 角色 |
| 主/次/提示文字 | `textPrimary` / `textSecondary` / `textTertiary` | 与实际表面组合检查对比度 |
| 链接、重点与图表 | `primary` / `chartExpense` | 对应 brand 角色 |
| 主操作及其文字 | `buttonPrimary` / `buttonPrimaryText` | 成对使用 action / onAction；深色可使用浅底深字 |
| 应用内数字键盘 | `keypadBackground` / `keyDigit` | 用于训练等既有业务键盘；记账金额使用系统输入法 |
| 线条 | `divider` / `border` | 分隔线和外边框不得混为同一用途 |
| 错误、成功、警告 | `error` / `success` / `warning` | 保留业务色义 |
| 遮罩与反馈 | `overlay`、Toast 相关角色 | 不在页面复制固定黑/白遮罩 |

选中分类等使用实心动作表面时，背景和图标同样使用 action / onAction 配对。不能假定品牌色和动作色永远相同，也不能假定深色主题上的所有按钮文字都是白色。

卡片优先使用 `AppTokens.cardDecoration(context)` 或 `SectionCard`，统一读取卡片边框、阴影和质感。已有背景留白的父容器传 `margin: EdgeInsets.zero`，避免双重边距；强调表面可显式传色或使用 `hero`，不叠加普通卡片纹理。

- 经典蓝保留柔和层次。
- 极简清单以细边框和平面表面为主。
- 温暖手账只在适合的主要表面使用轻阴影和纸面质感。
- 浮动动作、弹层分别消费 `fabShadow`、`sheetShadow`；不能用固定 Material elevation 代替所有主题的阴影。
- `shadows.dart` 中的静态工具不作为三主题表面的配色和几何来源。

`cardInnerDividerColor` / `cardDivider` 与 `divider(context)` 共用当前皮肤的 `line`，浅色和深色均保持可见；厚度由 `DividerTheme` 决定。不要通过透明色或零高度另藏一套暗色分隔规则。

账单行的分隔线从正文左缘开始，图标区域不画线，末行不补多余分隔。缩进由共享行的实际内边距、图标宽度和间距计算，不把网页原型的绝对坐标硬编码到 Flutter 页面。

## 4. 文字与系统缩放

`MainApp` 保持应用比例 1.0，直接继承系统 `TextScaler`，包括平台提供的非线性无障碍放大；不额外乘 0.85，也不把系统比例强行改成线性值。常规文字收敛通过字号 Token 完成，布局和点击区域不跟随整体缩小。

| 用途 | 入口 |
| --- | --- |
| 正文/标签/说明 | `body`、`label`、`caption` |
| 页面与分组标题 | `title`、`strongTitle`、`domainTitle` |
| 展示数字 | `display1/2/3`、`moneyHero`、`heroNumber` |
| 可编辑金额与币种符号 | `amountInput` |
| 日期与时间辅助文字 | `dateSecondary` |
| 连续阅读 | `documentBody` |
| 四域底栏 | `bottomNavigation` |

温暖手账只在 `domainTitle`、`moneyHero` / `moneyHeroFraction`、`heroNumber` 使用系统衬线候选。普通标题、正文、分类、表单、导航、货币符号、金额输入和训练数字键盘保持无衬线。金额输入要使用 `amountInput`，不要直接把展示金额字体用于可编辑数字。

当前基础字号为：正文与普通输入 12、标签 11、小说明 10、日期辅助 11、列表标题 14、业务大标题 22、display1/2/3 为 20/22/28、记账主金额 36（小数 24、符号 16）、日子主数字 48、四域底栏 16；装饰眉题 9。尺寸不随三套皮肤改变，皮肤只调整相应字体家族与字重。

字号、字重及行高以 `AppTypography.buildBase` 和对应 Token 为准，不在页面重新复制常量。普通界面使用系统字体与回退候选。中文与数字混排、字体候选回退需要 Android/iOS 实机确认。

窄屏和大字号处理：

- 可增高的标题、按钮、说明优先自然换行；分类网格按字体字号、行高和 `TextScaler` 计算行高。
- 金额和表达式保留完整输入；长文本可自然换行，不截断或重写保存值。货币符号与输入首行基线对齐，币种和本笔汇率操作保持可达。
- 固定币种符号槽使用单行 `FittedBox(scaleDown)`：选择器圆形槽与共享 56dp 列保留完整符号，名称列起点一致；不压缩整个列表文字或操作热区。
- 七列日历、底部固定导航和训练数字键盘可按组件现有规则限制局部缩放；通过提示、读屏和详情补充完整内容。
- 按 360px 和系统 100% / 130% / 160% 字号检查，尤其是编辑器、长名称和系统键盘同时出现的状态。
- 文本、点击区域、错误提示和焦点可见性分别验收，不能只检查静态截图。

## 5. 四域导航与功能入口

[AppShell](../lib/shell/app_shell.dart) 底部固定纯文字「记账、日子、备忘、健身」，业务内导航由 [DomainHeader](../lib/shell/domain_header.dart) 承载。四域当前本入口以本子名和下拉箭头紧邻业务标题，不绘制常驻底色框，与日历、头像处于同一行；长本名可省略并通过 Tooltip 查看完整名称，保留按钮点击区域。

| 业务 | 顶部页签 | 当前本入口 | 新增 |
| --- | --- | --- | --- |
| 记账 | 明细、统计 | 选择账本 / 管理账本 | 记一笔 |
| 日子 | 日子、工具 | 选择日子本 / 管理日子本 | 记日子 |
| 备忘 | 备忘录、账号密码、工具 | 普通备忘与账号密码页签各自选择当前本 / 管理两类本 | 当前页签对应的新记录 |
| 健身 | 训练、计划、统计 | 选择训练空间 / 管理空间 | 训练、模板或计划 |

页头日历进入同一份跨业务日历；头像进入「我的」。共享页面返回时恢复原业务及页签。域内次级页签返回先回该域首页，首页双击返回确认退出。重复点击或长按底栏不再隐式切换业务；默认首页与旧两域快捷切换设置已删除，不新增另一套启动业务偏好。

首次欢迎页展示主标题和四个业务域，不显示主标题下的副标题，只提供完成操作；默认偏好为 CNY，不展示币种选择框，不改已有账本本位币，也不提前创建默认本。初始化失败保留重试。

四域页头不再提供「本机／云端」捷径；当前本选择与管理入口仍在，存储类型继续在本选择器中显示。云服务、同步、备份等完整入口仍由「我的」和原管理页面承接。

调试构建在域内页签行末端显示 `AcceptanceSeedAction`，受 `kDebugMode` 限制；正常发行构建不显示。它不作为新增业务功能计入原有功能基线。

四域首页、统计与工具正文由业务壳统一承载标题、安全区和本管理入口。具有独立路由的账号密码列表与健身计划管理页保留各自的页面入口。以下能力必须继续可达：

- 账本基本设置、成员、成员统计、AA、周期记账、归档和存储生命周期操作，由当前账本弹层的管理入口进入。
- AA 统计位于账单标题旁，仅按账本 AA 开关控制。
- 日子首页的本选择与管理由 `DomainHeader` 承接。正文使用最近事件卡、选日导航和分类记录列表；选日改变展示基准，完整分类记录保持可见。
- 普通备忘页只展示普通内容列表；账号密码通过独立页签进入，并使用独立当前本、搜索与记录列表。普通备忘不增加搜索；各页签新增动作落在相应记录类型，工具页仍可选择新建类型。
- 备忘工具的普通本与账号密码本各自展示选本、选记录、格式、导出全部控件。无本、空本、加载、失败和未完整下载只影响状态与可用性，不隐藏整套工具；导出条件不足时禁用按钮，格式仍可选择，失败提供相应重试。普通本保持单选记录，账号密码本默认全选并可调整，两类上下文互不覆盖。
- 健身「计划」页签中的「我的计划」「我的模板」各只在标题右侧提供「查看全部」，分别进入原独立管理页；新增和内容库由管理页承接，卡片与菜单保留。
- 健身「训练」页签只展示日期导航和所选日期的训练或休息安排；计划与模板集中在「计划」页签，不展示本周完成摘要。训练卡沿用生产版紧凑布局，显示图标、动作组进度、状态、时长和更多菜单，点击进入详情；日期卡下不展示说明图例，日期格状态标记保留。
- 「我的」保留账户、语言、提醒、主题、应用锁、迁移、云服务、分类、汇率、动作库与默认休息。检查更新仍受原生 Android 条件限制。
- 空本、加载失败和只读状态需要保留适用的管理、重试或新建路径。权限和平台条件沿用业务规则，不能因为换版式放宽权限。

原型中未批准的普通备忘搜索/置顶/标签、记账搜索、日历业务筛选、账号密码独立验证、周训练目标和新增法定假期安排，不应借 UI 重构加入。已有账号密码搜索、农历和节日日期继续保留；法定假期与调休的休/班角标及对应读屏信息不展示。

## 6. 记账编辑器与金额展示

[TransactionEditorSheet](../lib/features/transactions/presentation/widgets/transaction/transaction_editor_sheet.dart) 使用底部自定义计算键盘。新建金额从 `0` 开始，编辑已有记录时回填原币金额；金额不唤起系统输入法，备注使用独立的系统文字输入。训练数字键盘继续服务训练业务。

页面结构：

1. 常驻头部：返回、标题、适用的协作作者信息和 AA 分摊方式，保存由底部完成键承接。
2. 分类采用五列纵向网格，一级分类独立滚动。选择含子项的父分类时，在父行下方原位展开子分类卡；子卡圆角为 20dp，最大可视高度为 200dp，长子列表可独立滚动。父分类也可直接提交。
3. 编辑分类是分类区底部的图标与文字入口。无分类或查询失败仍提供管理入口；共享非 owner 按业务规则禁用入口并保留权限提示。
4. 底部输入区依次为整行备注、金额栏和四行计算键盘。金额栏的币种占一列、金额占两列、删除占一列；下方包含数字、四则运算、日期与时间、小数点和等号/完成键。底排四个按键使用同一宽高约束，文字缩放不改变背景尺寸。
5. 错误反馈位于金额输入区，使用 liveRegion 和完整 Tooltip；失败保留金额、分类、备注和日期草稿。

弹层使用全高布局，顶部圆角为 16dp。分类区填满底部输入区以外的空间；键盘目标高度按屏高的 40% 计算，限制为 320～360dp。输入区保留 8dp 顶部及水平间距、40dp 底部间距；大字号备注按实际字体高度留足空间。短屏或备注系统键盘展开时，底部输入区可独立滚动到全部键位，输入组件保持挂载。编辑器统一处理系统键盘与底部安全区，返回键先收起备注键盘。

分类准备与账本上下文：

- 首页预加载当前账本的分类树，普通记一笔复用相同的查询实例和本机数据，关闭与重开不会新增分类订阅。
- 编辑已有记录使用记录所属的账本 ID，目录、本位币、AA 及保存目标均绑定该账本，首页当前选择保持不变。
- 入口从准备阶段到弹层退出持续持有账本和分类订阅。已预加载数据同步命中；冷目录只在弹层出现前等待本机首值，首帧直接回填分类选择。
- 准备完成后复核账号、身份代次、目标账本及普通新增的当前选择，失效时给出安全提示并阻止打开。普通账务刷新不重启分类订阅，分类内容仍由数据库监听实时更新。
- 分类删除、目录失败或父项不可见时解除可提交选择；查询和重试绑定同一账本，不能提交其他目录或孤儿子分类。

金额输入与保存：

- 数字和运算符按下生效，手指滑出回滚该次输入；删除键退一位，长按清空。连续运算符替换末尾符号，不把待输入的操作数当成零。
- 表达式最长 512 字符，每个操作数最多 28 位整数、2 位小数。草稿保留未完成式，输入不能静默转成另一金额。
- 表达式使用受限的 Decimal/Rational 解析，乘除优先于加减；中间乘除保持有理数精度，最终使用 round-half-even 到两位小数。它不执行代码或读取外部数据。
- 运算式先通过等号求值，下一次完成手势松手后才保存；等号与完成不会在同一次手势内连续执行。未完成式、语法错误、除零、超限、零或负结果均不可保存，负结果保留符号。
- 未完成式可预览当前完整前缀：`30+` 显示 `30`、`30+2×` 显示 `32`。预览不代表可以保存，除零或超限不使用历史缓存金额代替结果。
- 外币保留币种选择、本笔汇率编辑和折算预览，编辑时沿用隐含汇率；汇率取消保留草稿。备注最多二十字，备注 Done 只结束文字输入。
- 金额草稿、备注控制器和分类滚动状态由各自组件持有，主题、尺寸和键盘变化不重建输入资源。保存期间锁定操作，失败解除锁定并保留草稿；AA 和交易事务保持既有业务边界。
- 日期键使用同一排五列滚轮选择年月日时分，取消保留完整原值。

经典、极简和手账主题共用上述交互结构，颜色与字体使用语义 Token；金额使用无衬线 `amountInput`。备注、金额栏及计算键使用 4dp 圆角，数字和操作符按行高设置字号，日期辅助与分类标签保留对应字体角色。三主题浅色、深色及大字号均需保持分类、底部按键和错误反馈可读。

Android/iOS 的备注输入法、系统返回与键盘伸缩仍需设备验收；模拟 insets 的 Widget 回归验证对应布局和状态。
`AmountText` 与首页账单金额默认使用中性色，错误和警示色只用于实际业务状态。首页汇总、今日/本周支出和统计继续使用真实账期、折算及排除规则。

首页主金额下方不显示同期比较或「已记录」说明；每日支出趋势仍保留。极简主题的首页账单明细直接平铺日期分组和记录，不绘制外层卡片表面；日期和图标左缘、金额和日小计右缘使用页面统一的 20dp 边距，不叠加卡片内边距，账单标题后只保留日期行自身间距。经典与手账主题保留整月卡片。各主题共用记录数据、详情/分类点击、长按删除、AA 标记与虚拟列表，底部新增按钮留位不依赖卡面。

## 7. 共享布局与表单

- `PrimaryHeader` 承担独立页面安全区和标题；壳内页面通过 `embedded` 避免重复头部。对象详情头使用 `AppDetailHeader`。
- `MainApp` 的 `AnnotatedRegion<SystemUiOverlayStyle>` 使用 `PrimaryHeader.systemOverlayStyle` 为状态栏提供统一的主题前景托底；移除页面头部后仍保持明暗可读。顶部布局安全区继续由 `DomainHeader`、独立 `PrimaryHeader` 或相应页面处理，不把状态栏图标样式和内容留白混为同一职责。该 helper 不设置系统导航栏颜色，系统导航栏应独立按平台验证。
- `SectionCard`、`AppFormSection`、`SelectableCard` 共享主题表面与形状；选中边框/角标不能覆盖普通卡片的默认样式。
- `AppSelectionField` 与 `AppDateField` 共享 `AppInputSurface`；填充、边框、点击形状和禁用状态来自最近的输入主题。
- `AppDialog` / `AppContentDialog` 使用最近的 `DialogTheme`；复杂内容可滚动，操作通过原生布局在窄屏换行。
- `AppSheet` 的标题、内容和底部操作分区复用通用组件。普通弹层最大高度默认由 `kAppSheetHeightFactor` 控制，记账编辑器按内容收缩、以屏高与最小 28dp 顶部间隔限制最大高度，并自行避让键盘；不要在内容中再次扣减同一安全区或键盘高度。
- 弹层默认颜色、形状和阴影跟随当前主题；显式覆盖（例如特定透明遮罩）必须是该入口的明确交互决定。
- `AppRadioTile` 处理单选视觉与语义；方向键、空格及互斥选择沿用现有分组机制。
- `AppEmpty` 和 `AppLoadError` 复用空态布局，失败态提供重试。内容为空时仍需保留下拉刷新需要的可滚动容器。
- `AppPullToRefresh` 承接真实本地/云端刷新结果，不以换主题或换版式替代原有同步协调器。
- 浮动新增按钮独立于四域底栏，列表尾部预留 `domainBottomClearance`，确保最后一项和操作不会长期被 FAB 遮住。

## 8. 日历、统计与其他共享组件

日历使用 `AppCalendar`，共享农历/节日日期、选中日期、金额和业务标记。法定假期与调休的休/班角标及对应读屏信息不展示，不改变农历和节日日期本身；健身计划中的业务休息日仍保留。日历像素滚动与内部翻页状态各自使用独立存储作用域；不能把外层列表像素位置当成内层页码。日期圆、行高和星期行使用专用尺寸 Token。大字和多条标记按实际内容扩展行高。

- 全局日历保留原有日期导航和五类新增。「回到今天」位于日历标题同排右侧，仅选日不是今天或聚焦年月不是本月时显示，返回后隐藏；本地当天来源与日期数据保持一致。共享日历的返回键恢复原业务和页签，不再叠加第二个标题栏。
- 健身日期卡的「回到今天」也只在偏离今天时出现。周/月范围保持完整单行，必要时仅缩放日期文字并提供完整 Tooltip；左右箭头和展开热区保留原尺寸，不能以裁掉日期或缩小点击区域解决换行。
- 健身首页嵌入业务壳时将日期格横滑交给域内页签；日期范围通过箭头选择。独立日历保留默认横滑。
- `AppCalendar.rangeOnly` 用于限定范围的计划编辑，复用日期与标签绘制，不另造一套日期样式。
- 日子工具直接展开节日列表，不为现有日期差和日期推算增加折叠或新的业务筛选条件。

统计共用 `AppAnalyticsPeriodHeader` 与 `AppAnalyticsPeriodSwitcher`。壳内周/月/年放在顶部，日期滚轮、子周期和回到当前周期继续工作。账期不再由记账内容区的横滑改变。

记账统计趋势使用 `AnalyticsLineChart` 绘制现有查询结果，数值单位为账本本位币金额，日期轴与提示沿用 `AnalyticsAxes`。周视图用星期简称且无额外尾缀，月视图用实际日期并标「日/Day」，年视图用 1..12 并标「月/Month」；当前年度未来月份保留刻度，不伪造折线数据点。分类饼图与排行保留数值、占比和详情入口。首页每日支出曲线继续复用账期、折算和排除统计规则。健身等非金额统计可使用 `AnalyticsLineChart.valueFormatter`；缺失值 `double.nan` 保留断点，不补成真实零值。

记账统计顶部只展示总支出与趋势，不展示环比和日均支出；对应的上一周期查询与专用展示计算不参与页面加载。总金额按可用宽度完整显示，统计日期行的返回当前周期操作在分配宽度内换行，不挤出日期入口。

健身统计先判断当前空间和查询状态：无空间显示空间空态；目录或统计读取失败显示真实错误与重试；只有云空间未完整下载或过期时显示下载提示。本机空间的异常不能表述为云端未下载；其他运行训练冲突保留同步中心入口。有效完整空间继续使用原训练统计数据与周期规则。

动作库与选择动作复用动作卡片、筛选和缩略图；窄屏/大字不足以容纳侧栏时使用既有选择器。训练计划、模板和训练过程的日期、排序、休息、组输入与计时，继续由原组件和用例管理。不得为了迁移首页入口复制业务逻辑。

## 9. 跨业务复用与边界

以下约束与主题无关，继续保留：

- 日子本、备忘本、训练空间编辑复用 `PrivateBookEditor`，统一名称字段、忙碌状态、身份校验、创建重试和存储确认。
- 普通名称使用 `normalizeName`；密码和正文不走名称规则。创建、编辑、导入、恢复和同步使用同一校验入口。
- 私有本共用 `PrivateBook` 元数据、当前本选择与目录状态；财务共享权限、日期历法和协议载荷留在业务适配层。
- 导入目标复用 `ImportBookSelector`；账号、会话代次与同步绑定变化时重新校验，不把旧任务写到新账号。
- 同步/备份时间使用统一时间格式化入口，提示与同步中心复用同一事实查询。
- AA 均分保留整分与 Decimal 余数处理；主题、图表和输入排版不能改变分摊总额。
- 错误日志记录操作和异常堆栈，界面显示可理解的错误；不把账单正文、密码或凭据写入日志。

## 10. 实施与验收

示例：

```dart
Container(
  decoration: AppTokens.cardDecoration(context),
  padding: const EdgeInsets.all(AppDimens.p16),
  child: Text(
    '内容',
    style: AppTextTokens.body(context),
  ),
)
```

验收顺序：

1. 核对原有入口及权限/平台条件：可迁移入口位置，不得无意隐藏保留功能。
2. 核对三主题 × 浅深色，包含普通、禁用、选中、错误、按下和焦点状态。
3. 核对窄屏、大字号、长名称、外币金额、系统键盘与弹层叠加。
4. 核对主题变化后的路由、日期、滚动、草稿、选择及持久化失败重试。
5. 运行本地静态分析和相关业务逻辑测试，人工检查真实 Flutter 截图与页面交互，再做 Android/iOS 实机字体、辅助技术与触摸验收。

自动测试只覆盖必要业务规则；主题、字号、间距、布局和页面交互按上述步骤人工验收。测试失败必须按需求诊断为实现错误或测试错误；金额、权限、保存结果或保留功能丢失属于实现问题。CI 仍按项目规则执行，未经明确同意不启动或重跑。
